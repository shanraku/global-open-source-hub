# Contributing

Thanks for helping make useful open-source software easier to discover.

## Suggest a project
Open a GitHub issue with:
- Project name and original public repository URL
- One or two sentences describing its practical use
- Main category and useful keywords
- Link to its license and documentation
- Any important limitations or external data sharing

## Improve an existing entry
Edit `data/projects.json`. Keep descriptions factual and concise. Preserve the JSON structure and use the original repository URL.

## Quality checklist
- Is the project genuinely useful and publicly accessible?
- Does the repository explain how to use or build it?
- Is the license clear? Do not assume a repository is open source merely because it is public.
- Are security, privacy, pricing and availability claims supported?
- Is the project distinct from entries already listed?

## Pull requests
Explain what changed and provide source links. Do not add credentials, personal information, tracking scripts or unverified metrics. Maintainers may request evidence or decline submissions that do not meet the directory policy.
