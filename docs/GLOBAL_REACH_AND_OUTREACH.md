# Global reach and community outreach

## Mission
Help developers, students, educators, researchers and open-source communities discover useful public projects and contribute back. Reach must be earned through usefulness, transparency and respectful participation—not spam or inflated metrics.

## Before public promotion
1. Publish the site on a stable public HTTPS URL and verify that it works on mobile.
2. Confirm the final public URL, then add canonical URL, sitemap.xml, robots.txt and Search Console/Bing Webmaster verification using that exact URL. Do not publish placeholder or guessed URLs.
3. Confirm the catalogue links, license notices, contact/reporting route and contribution instructions.
4. Run the repository's planned tests and accessibility checks with maintainer approval before announcing a production launch.
5. Add a short, accurate project description and social preview image; never imply global completeness, security certification or endorsement.

## Discovery channels
- Search engines: descriptive page titles, useful category pages, crawlable links, accurate metadata and a sitemap after the production domain is confirmed.
- GitHub: README, topics, releases, discussions/issues, contribution guide and links from related repositories where genuinely relevant.
- Developer communities: share in communities that explicitly allow project launches and open-source directories; follow each community's self-promotion rules.
- Education: invite teachers, student clubs, coding communities and university open-source groups to suggest useful resources.
- Open-source events: submit to relevant community newsletters, directories, meetups and hackathons when submissions are open.
- Social platforms: publish occasional progress notes, newly curated collections, contributor stories and transparent changelogs. Link to source projects and invite corrections.
- Maintainer partnerships: ask upstream maintainers whether they want to be listed; make removal/correction easy.

## Suggested rollout
### Phase 1 — Foundation
Confirm public hosting, final domain, mobile experience, accessibility, sitemap, robots policy, structured metadata and a clear issue/PR path.

### Phase 2 — Small, relevant launch
Invite a small group of maintainers, educators and developers to review the directory. Fix confusing entries and collect specific feedback before wider promotion.

### Phase 3 — Community distribution
Submit to relevant open-source directories and newsletters, participate in discussions where the directory directly answers a question, and publish transparent launch notes.

### Phase 4 — Sustainable growth
Publish useful category collections and monthly change summaries. Thank contributors, respond to corrections, and remove stale or misleading records. Measure useful outcomes such as valid contributions and corrected entries—not vanity traffic alone.

## Share-ready short description
Global Open Source Hub is an independent, community-oriented directory for discovering practical open-source software. It links to original source repositories, explains its review approach, and welcomes corrections and contributions. Search coverage is growing but is not a complete index of every project worldwide.

## Share-ready launch post
We're building Global Open Source Hub: a growing directory to help developers, students and curious learners discover practical open-source software and go straight to its source.

The goal is simple: make useful projects easier to find, keep project information honest, and welcome community corrections and contributions.

Explore the repository: https://github.com/shanraku/global-open-source-hub

This is an evolving directory, not a complete index or a security endorsement. Suggestions and constructive feedback are welcome.

## Community conduct
- Read rules before posting; ask moderators when self-promotion rules are unclear.
- Never mass-DM, scrape member lists, buy engagement or post repetitive promotional comments.
- Disclose that you maintain the project when sharing it.
- Do not claim partnerships, endorsements, user counts or search-engine rankings without evidence.
- Respect takedown, correction and privacy requests.
- Keep posts useful: share a specific collection, improvement, methodology or contribution opportunity—not just a bare link.

## Metrics worth tracking
Prefer privacy-respecting aggregate measures where available:
- Valid project submissions and accepted contributions.
- Correction reports resolved.
- Maintainer opt-ins and confirmed project links.
- Broken links fixed and stale metadata corrected.
- Accessibility issues resolved.
Do not add invasive tracking by default. Report limitations and avoid collecting personal data.
